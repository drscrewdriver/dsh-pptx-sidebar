# dsh-pptx-sidebar

[简体中文](README.md) | [Français](README.fr.md) | [Deutsch](README.de.md) | [Italiano](README.it.md) | [Русский](README.ru.md) | [Español](README.es.md)

> ⛔ **Проект больше не поддерживается (2026-10-01).** В новых версиях хоста DSH есть встроенный предпросмотр office-презентаций в боковой панели, поэтому плагин больше не сопровождается — новых выпусков и адаптации к будущим линиям хоста не будет. Опубликованные версии остаются доступны для установки; для хостов 0.1.x используйте сборки из замороженных веток `compat/0.1.7` / `compat/0.1.5`.

Читайте презентации `.pptx` / `.pptm` в боковой панели DSH — слайды **в
порядке показа**, с их текстом, уровнями маркеров, заметками докладчика и
встроенными изображениями.

> **Это режим чтения, а не воспроизведение слайда.** Никакого абсолютного
> позиционирования, никаких шрифтов темы, никакого наследования заполнителей,
> никакой анимации. Просмотрщик сообщает об этом в своём заголовке: различие
> в вёрстке, выглядящее как ошибка отрисовки, хуже явно обозначенного
> ограничения.

Это потребитель [dsh-better-sidebar](https://www.npmjs.com/package/dsh-better-sidebar):
он регистрирует просмотрщик файлов и отображается внутри области предпросмотра
карточки Side. Без этого плагина он загружается, один раз выдаёт предупреждение
и ничего не делает.

## Установка

```bash
dsh plugin --profile <profile> add github:drscrewdriver/dsh-pptx-sidebar#<sha>
dsh plugin --profile <profile> add dsh-pptx-sidebar@0.1.0     # once published
```

Затем **перезапустите хост DSH** — обновления страницы в браузере недостаточно,
чтобы появилась новая строка загрузчика. Проверка, ничего не запуская:

```bash
dsh --profile <profile> --dump-config | Select-String dsh-pptx-sidebar
```

Ручная установка состоит из трёх шагов, а не одного — см. `cordis.patch.yml`.
Если выполнить только шаги 1 и 3, получится профиль, где пакет присутствует,
строка патча присутствует — **и ничего не загружается, молча**.

## Что делает / чего не делает

| Сделано | Не сделано |
|---------|------------|
| Список слайдов в порядке `p:sldIdLst` | Визуальная вёрстка, абсолютное позиционирование |
| Текстовые абзацы, уровни маркеров по абзацам | Разрешение шрифтов темы/образца |
| Определение заголовка по типу заполнителя | **Наследование заполнителей** (см. ниже) |
| Заметки докладчика из частей `notesSlide` | Диаграммы, отрисованные как диаграммы |
| Встроенные изображения как blob URL | Анимация, переходы, тайминги |
| Настоящие таблицы (`a:tbl`) | Комментарии, отметки рецензирования |
| Полужирные/курсивные фрагменты (runs) | Редактирование, запись обратно |
| Семь предохранителей | Устаревший `.ppt` (BIFF/OLE2), форматы WPS |

### Строка о наследовании заполнителей (сознательное решение)

Слайд часто показывает текст, которого в нём нет: номера, нижние колонтитулы
и текст заголовка, живущие в `slideLayout` / `slideMaster` и упоминаемые через
заполнитель `p:ph`. Разрешать их — значит заново реализовывать цепочку
наследования PowerPoint, включая переопределения уровней `lstStyle` и то,
какой макет слайд использует на самом деле.

**v1 этого не делает.** Читается только собственная часть слайда.
Последствие заявлено открыто, а не спрятано: слайд, текст которого полностью
унаследован, отображается без текста. Это видимое упущение, а не повреждение —
обратный компромисс (наследовать неверно) показал бы текст, которого на слайде
нет.

## Адаптация к ширине

Область боковой панели изменяема по размеру, поэтому режим чтения
подстраивается под неё — в определённых пределах, ведь «адаптивность» не
является лицензией на бесконечный рост или сжатие:

| Регулятор | Значение | Почему |
|-----------|----------|--------|
| Базовая ширина | 360 px | Здесь коэффициент **равен ровно 1**, поэтому при обычной ширине области вёрстка выглядит так, как её поставил 0.1.0 |
| Нижняя граница | 0.9× | Узкая область всё ещё получает читаемый текст |
| Верхняя граница | 1.15× | Широкая область получает комфортный, а не огромный текст |
| Квантование | 2 знака | Перетаскивание перевёрстывает содержимое шагами по 0.01, а не на каждом пикселе |

Коэффициент вычисляется из ширины области и записывается в пользовательское
свойство `--reader-scale`; базовый размер шрифта становится `13px × scale`,
а содержимое слайда выражено в `em`, поэтому текст **перетекает** (reflow)
под новый размер, а не масштабируется трансформацией (это размывало бы глифы).

**Масштабируется только документ.** Заголовки, маркеры, абзацы, заметки,
таблицы и подписи следуют за коэффициентом; полоса заголовка, полоса слайдов,
баннер предохранителя и состояния загрузки/пустоты сохраняют фиксированный
размер. Обрамление интерфейса, меняющее размер при перетаскивании разделителя,
воспринимается как сбой, а не как отзывчивость.

Два связанных решения:

- **Неизмеримая ширина откатывается к 1**, а не к границе. До первого
  измерения ширина равна 0, и отрисовка её как «как можно уже» заставляла бы
  крошечный текст вспыхивать при каждом открытии презентации.
- **Изображения не масштабируются.** Они отображаются в размере, заданном
  трансформацией фигуры, и ограничены только областью; увеличивать растровое
  изображение сверх его естественного размера вслед за текстом значило бы
  делать его более размытым, а не более точным.

## Конвейер

```
archive bytes (host /sidebar/file, custom loader)
  → archive-size gate                      refuse before any unpacking
  → central directory (declared-size gate) refuse a lying part before inflating
  → streaming inflate + total budget       the zip-bomb gate
  → ppt/presentation.xml                   p:sldIdLst — slide ORDER
  → ppt/_rels/presentation.xml.rels        rId → slides/slideN.xml
  → ppt/slides/slideN.xml                  p:spTree → p:sp / p:pic / p:graphicFrame
  │     p:txBody → a:p → a:pPr@lvl (level), a:r → a:rPr(b/i) + a:t
  │     p:pic    → a:blip@r:embed → slide rels → ppt/media/*
  │     p:grpSp  → recursed, never flattened away
  ├→ ppt/slides/_rels/slideN.xml.rels      .../notesSlide → notesSlides/notesSlideN.xml
  └→ rules: a slide too long loses only its own tail; notes absent is silence
```

Изображения извлекаются из zip и превращаются в object URL. Встроенное
изображение живёт *внутри* архива, поэтому не существует маршрута хоста, на
который можно сослаться — это не «чтение файлов самостоятельно», а
использование байтов, которые хост уже передал.

## Семь предохранителей

| Измерение | По умолчанию | Сверх него |
|-----------|--------------|------------|
| Размер архива | 8 MB | ЗАБЛОКИРОВАНО — отказ до любой распаковки |
| Суммарная инфляция | 64 MB | ЗАБЛОКИРОВАНО — защита от zip-бомбы |
| Одна часть | 32 MB | ЗАБЛОКИРОВАНО — одна чрезмерно большая XML-часть |
| Слайды | 300 | УСЕЧЕНО — читатель прекращает обход презентации |
| Текст слайда | 20 000 символов | остаток текста этого слайда опускается |
| Изображения | 200 | дальнейшие изображения пропускаются |
| Одно изображение | 8 MB | это изображение пропускается (даже не распаковывается) |

**Не более одного предупреждения на измерение**, причём структурно —
предупреждения живут в `Map<reason, warning>`, поэтому измерение,
срабатывающее на каждом слайде, даёт одну строку, а не шестьдесят.

Ограничение текста на слайд усекает только виновный слайд. Ограничение на
блок подрезало бы все слайды одинаково и теряло бы информацию, на которую у
презентации был бюджет; режим отказа, который мы принимаем вместо этого, —
«слайд 12 обрезан».

## Тесты

```bash
npm install
npm run verify          # build (bundle load gate) + tests
npm test                # 19 checks
```

Фикстура — настоящий zip в форме pptx, собранный в самом файле тестов, с
подлинным крошечным PNG. Он враждебен ровно там, где враждебен формат:

- `p:sldIdLst` перечисляет **слайд 2 раньше слайда 1**, поэтому сортировка
  частей по имени файла прошла бы все остальные проверки и всё равно была бы
  неверной;
- одна связь слайда использует **абсолютную** цель, другая — **External**;
- `ppt/slideLayouts/slideLayout1.xml` содержит `MASTER TEXT MUST NOT APPEAR`,
  что никогда не должно проявляться — именно это здесь означает «никакого
  наследования заполнителей».

## Устройство

| Файл | Роль |
|------|------|
| `pptx.ts` | Читатель: части, связи, дерево фигур, заметки, изображения |
| `circuit-breaker.ts` | Семь предохранителей и правило «одно предупреждение на измерение» |
| `zip.ts` / `xml.ts` | Чтение контейнера; адресное сканирование XML со счётчиком глубины |
| `PptxViewer.tsx` | Полоса слайдов, отрисовка текущего слайда, время жизни object URL |
| `locales.ts` | Словари zh / en, включая каждый шаблон предупреждения |
| `seams.ts` | Структурные зеркала используемых сервисов клиента |

Код zip и XML **скопирован** у соседнего плагина документов, а не разделён.
Два потребителя этого кода — ещё не порог для выделения пакета: это добавило
бы третью сущность, которую нужно публиковать и фиксировать по версии.
